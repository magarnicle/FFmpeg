Differences between deck.txt (our teletext) and poli.txt (old Polistream system)
================================================================================
Caption text contents excluded. Generated from teletext_tools/vbi_compare.py.

REVISED 2026-09-18. Both cards are digital 3G-SDI, so poli.txt is bit-exact (no analog
noise). An earlier revision wrongly blamed "capture artifacts": the real cause was that
our bit-slicer mis-timed poli's more heavily-shaped waveform. With per-file timing
recovery both files now decode at ~96% valid Hamming, and these are the true differences.
Each is annotated: EXISTING flag, CAN-ADD flag, or NOT-A-SETTING (program/capture).

WHAT POLI'S X/31 FILLER IS
poli's idle line carries Packet 8/31 = an Independent Data Line (IDL / teletext
datacasting): MRAG mag 8 row 31, a format byte, a fixed service-address run (0xC7 x5),
a continuity counter (byte 10, +1 per packet), then user data that changes every packet.
It is a live data service riding alongside the visible page-801 subtitles, not dummy-
header filler. Its content is not identifiable without the datacast service spec.

REAL DIFFERENCES
A. Clock-run-in start: deck ~sample 2, poli ~sample 6-7.
   FLAG (EXISTS): -teletext_vbi_offset 6  (we run 2 for the Foxtel source).
B. Black level (min): deck = 15, poli = 16.
   deck's 15 is a 1-LSB shaping undershoot below black. NO flag (could clamp to 16).
C. Binary-"1" level (max): deck = 161, poli = 160.
   FLAG (EXISTS): -teletext_level 66 (default; ~160-161). Essentially matched.
D. Waveform sample levels: deck = 8 distinct, poli = 65.
   REAL: Deltacast shapes its waveform far more finely than our raised-cosine. This is
   genuine, not noise. NO flag yet; would need higher oversampling in our shaper.
E. Idle filler packet: deck = 8FF dummy header; poli = Packet 8/31 IDL datacast (above).
   FLAG (CAN ADD): a filler-type toggle. CAVEAT: poli's X/31 is a live datacast whose
   payload changes every packet, so only the packet TYPE can be matched, not its content.
F. 8FF filler control byte 7: deck = 0x5E (C6=0, C7/C8/C9=0); poli's 8FF = 0xD0
   (C6=1, C7/C8/C9=1) - poli's dummy header carries the same control bits as its subtitle
   header. FLAG (CAN ADD): filler header control bits.
G. 8FF filler subcode: deck = 0x3F7E; poli = 0x0000.
   FLAG (CAN ADD): -teletext_filler_subcode.
H. Fields differing (line 21 vs 334): deck = 32/500 (8FF filler identical on both fields);
   poli = 500/500 (its X/31 datacast differs per field via the continuity counter).
   STATUS: consequence of E; follows automatically from an X/31 filler.

NOT DIFFERENCES (identical once decoded correctly)
- Subtitle header (page 801): byte 7 = 0xD0, C6 = 1, C7/C8/C9 = 1, subcode 0x0000. SAME.
  (Earlier "#12/#13 subtitle byte7/C6 differ" was a slicer error.)
- Magazine: 8 for both. The X/31 is mag 8, row 31 - not mag 4. (Earlier "#15" was wrong.)
- Framing code 0x27, page 801, region 0, C11 = 0, double-height rows, Start/End boxing.

NOT A SETTING (program content or capture)
- First frame number (deck 2, poli 3): capture start.
- Program video / signal-line count: both have video; different programs.
- Line mean luma, caption rows used, per-row box-code counts: program content
  (deck and poli are now different programs), or a side effect of E's X/31 payload.

SUMMARY - HOW TO MIMIC POLISTREAM (flags added 2026-09-18, commit 9cbc75596e)
- CRI position (A): -teletext_vbi_offset 6
- Level (C):        -teletext_level 66  (default)
- Filler type (E):  -teletext_filler idl        (8/31 IDL; type only, not poli's payload)
- Filler ctrl (F):  -teletext_filler_ctrl 1      (dummy filler C6/C7/C8/C9 = 1)
- Filler subcode(G):-teletext_filler_subcode 0   (poli uses 0; default 0x3F7E)
- Sample levels (D):-teletext_shape <lower>      (existing cutoff; 90=~9 levels, 50=~37;
                     lower approaches poli's 65 but trades against decode margin)
- Not matchable: poli's live X/31 datacast payload (no source); program content.

Closest single-command poli mimic (idle filler as 8/31 IDL, like poli):
  -teletext_vbi_offset 6 -teletext_level 66 -teletext_filler idl
Or keep 8FF dummy headers but match poli's control bits/subcode:
  -teletext_vbi_offset 6 -teletext_filler_ctrl 1 -teletext_filler_subcode 0
